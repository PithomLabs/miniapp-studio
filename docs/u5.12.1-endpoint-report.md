# U5.12.1 Verification — Endpoint Isolation Guard

Date: 2026-11-25. Bounded follow-up to `docs/u5.12-report.md`,
closing the one remaining condition on invariant 7
("No harness can reach live data").

## Condition

Database-name validation alone does not establish cluster
isolation: a mispointed TEST_DATABASE_URL could aim provisioning
at a remote or production cluster. Required: fail-closed
host/port allowlist enforced before provisioning, PostgreSQL 19
rejection, and tests proving rejection without dialing.

## Implementation (`testdb/testdb.go` only, no redesign)

- `CheckTestEndpoint` (pure, opens no connection): parses the
  bootstrap URL, requires scheme postgres, requires host in
  `{127.0.0.1, localhost, ::1}` and port exactly `5434`.
  Constants are named for single-point re-approval.
- Called first in both provisioning paths (`provisionRunDB`,
  `ScratchDSN`), before any connection is opened.
- `checkPG19` runs immediately after connecting and before any
  DDL: `server_version_num / 10000` must equal 19.

## Evidence

- `TestEndpointAllowlist` (pure table test): 3 acceptances,
  9 refusals (remote host, LAN IP, wrong/missing ports,
  trailing-dot localhost, empty host, wrong scheme,
  unparseable). No connections by construction.
- `TestEndpointRejectionPrecedesDial` (subprocess end-to-end):
  a child `go test` with TEST_DATABASE_URL aimed at the
  unresolvable `u512-unapproved.invalid:5434` fails with the
  allowlist refusal and provably never dials (no DNS/connection
  error text in its output). PASS.
- Full serial suite after the change: 15/15 packages ok;
  bootstrap database 1 build / 1 conversation before and
  after; run databases reaped after.

## Verdict

Invariant 7 is now fully closed: cluster isolation (endpoint
allowlist + PG19 gate) composes with database isolation (run-
pattern names, ignored database component, environment
rebinding). No commits made. Stopping per the authorization.
